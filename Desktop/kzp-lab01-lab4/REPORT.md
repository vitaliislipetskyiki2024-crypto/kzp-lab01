# Звіт до лабораторної роботи №1

## 1. Тема, номер і варіант
* **Лабораторна робота:** №1
* **Тема:** Розробка програми для обробки даних про кінотеатр
* **Предметна область:** Кінотеатр
* **Варіант:** №19
* **Операційна система:** Windows 10

## 2. Мета роботи
Метою лабораторної роботи є розробка консольної програми мовою Java для зчитування, перевірки та обробки даних про фільми в кінотеатрі.

**Досягнуті результати:**
Налаштовано Maven-проєкт, додано модульні тести JUnit 5, статичний аналізатор SpotBugs, Maven Wrapper та реалізовано формування виконуваного JAR-файлу.

## 3. Постановка задачі
Програма повинна зчитувати дані про фільми з CSV-файлу `data/input.csv`.

**Формат одного запису:**
```text
film;hall;ticketPrice;sold;durationMin

Чотири розрахункові показники варіанта 19:
Загальний виторг кінотеатру (сума ticketPrice * sold).
Середня тривалість фільму (середнє значення durationMin).
Найпопулярніший фільм (фільм з максимальним значенням sold).
Загальна кількість відвідувачів (сума всіх sold).

## 4. Структура програми
Структура файлів і пакетів (ua.lpnu.kzp):
data/input.csv — файл із вхідними даними.
Main.java — точка входу (запускає програму).
FileReport.java — читає CSV-файл, рахує 4 показники та формує звіт.
MainTest.java — тести (JUnit 5) для перевірки роботи.
Потік даних (від входу до звіту):
Вхід: Файл data/input.csv із текстом.
Обробка: FileReport.java зчитує файл рядок за рядком, розбиває дані по ; та обчислює 4 показники варіанта.

## 5. Інфраструктура
Система збірки: Apache Maven із використанням Maven Wrapper (./mvnw).
Залежності (pom.xml):
JUnit 5 — для написання та виконання модульних тестів у MainTest.java.
SpotBugs — для статичного аналізу коду на наявність багів та помилок.
Пакування: Налаштовано створення виконуваного .jar файлу в директорії target/.

## 2. Перебудова та нові компоненти (ООП)
Замість процедурної обробки сирих масивів рядків у `Main.java` реалізовано об'єктну модель:

1. **Клас-сутність `Screening` (Entity):**
   * Повністю інкапсулює дані про кіносеанс (`film`, `hall`, `ticketPrice`, `sold`, `durationMin`).
   * **Незмінність (Immutability):** Поля є `private final`, сетери відсутні.
   * **Валідація інваріантів:** Усі перевірки некоректних даних перенесені в конструктор.
   * **Статичний фабричний метод `fromCsv(String line)`:** Перетворив парсинг CSV у просту та безпечну операцію.
   * **Метод `calculateRevenue()`:** Інкапсулює розрахунок доходу від конкретного сеансу.

2. **Запис `TicketSales` (Record):**
   * Компактний immutable-контейнер для групування підсумкових показників роботи програми.

## 3. Додані тести JUnit 5 та що перевірено
У файл **`ScreeningTest.java`** додано новий набір юніт-тестів, які покривають усі сценарії використання моделей:

### Перевірені випадки:
* **Позитивні (Happy Path):**
  * `fromCsvCreatesValidObject()` — коректне створення об'єкта з CSV-рядка та правильність роботи методу `calculateRevenue()`.
  * `recordStoresCorrectValues()` — перевірка створення та читання полів `record TicketSales`.

* **Граничні випадки (Boundary Cases):**
  * Перевірка мінімальних допустимих значень (наприклад, ціна квитка = 0.0 або продано = 0 є коректними значеннями).

* **Негативні випадки (Negative Cases / Invariant Validation):**
  * `constructorRejectsEmptyFilm()` — генерація `IllegalArgumentException` при передачі порожньої назви фільму або `null`.
  * `constructorRejectsNegativeValues()` — перевірка захисту від номеру залу <= 0, від'ємної ціни, від'ємних квитків та тривалості.
  * `fromCsvRejectsInvalidFieldCount()` — перевірка викидання помилки при неправильній кількості полів у CSV (не 5).
  * `fromCsvRejectsInvalidNumberFormat()` — перевірка захисту від некоректного формату чисел (наприклад, літери замість ціни).
  * `recordRejectsNegativeValues()` — перевірка заборони від'ємних підсумкових показників у `TicketSales`.
