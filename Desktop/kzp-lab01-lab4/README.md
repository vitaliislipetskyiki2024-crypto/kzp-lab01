# Лабораторна робота №1 — Кінотеатр

## Призначення програми

Програма призначена для обробки даних про фільми в кінотеатрі.

Вона зчитує записи з CSV-файлу, перевіряє їх правильність та для правильних записів обчислює:
- кількість правильних записів;
- загальний дохід;
- середню ціну квитка;
- максимальну кількість проданих квитків.

Некоректні записи пропускаються та виводяться на екран.

## Формат вхідних даних

Вхідні дані зберігаються у файлі:

`data/input.csv`

Формат одного запису:

```text
film;hall;ticketPrice;sold;durationMin

Проєкт реалізує об'єктно-орієнтований підхід для обробки даних предметної області **Кінотеатр** (Варіант 19).

##  Структура проєкту та нові моделі

У цій лабораторній роботі було здійснено рефакторинг з процедурного підходу на об'єктно-орієнтовану модель:

1. **`Screening.java` (Клас-сутність / Entity)**
   * Описує окремий кіносеанс.
   * **Незмінність (Immutability):** Усі поля є `private final`, а сетери відсутні.
   * **Фабричний метод `fromCsv(String line)`:** Перетворює рядок CSV-файлу на об'єкт `Screening`.
   * **Бізнес-логіка:** Метод `calculateRevenue()` обчислює валову выручку з продажу квитків (`ticketPrice * sold`).

2. **`TicketSales.java` (Record)**
   * Незмінна структура даних (`record`) для підсумкових розрахованих метрик (`validRecords`, `totalRevenue`, `averageTicketPrice`, `maxSold`).

---

##  Правила валідації (Інваріанти)

Обидві моделі гарантують свою цілісність — спроба створити некоректний об'єкт викликає `IllegalArgumentException`:

* **Назва фільму (`film`):** не може бути `null` або порожньою (`isBlank()`).
* **Номер залу (`hall`):** має бути строго більшим за 0 (`hall > 0`).
* **Ціна квитка (`ticketPrice`):** має бути невід'ємною та скінченним числом (`ticketPrice >= 0` та `Double.isFinite`).
* **Продано квитків (`sold`):** невід'ємне число (`sold >= 0`).
* **Тривалість (`durationMin`):** має бути додатною (`durationMin > 0`).
* **Підсумковий звіт (`TicketSales`):** усі показники звіту мають бути невід'ємними.
